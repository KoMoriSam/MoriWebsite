## Overview

MoriWebsite is the frontend for KoMoriSam's personal website. It is designed around publishing and long-form reading, with static site generation (SSG) providing indexable article pages and complete SEO metadata.

The site currently includes:

- a responsive homepage with a profile, dynamic background, and contact links
- a blog with keyword, tag, and year filters
- the Markdown-driven original novel _Toward the Distance_ and a dedicated reader
- Pagefind-powered site-wide search across blog posts, novel chapters, and changelogs
- Giscus comments at article, chapter, and paragraph level
- online tools such as Minecraft server status
- changelogs, theme switching, reading progress, and local reader preferences

Production routes:

```text
/
/blog
/blog/:articleId
/novel
/novel/:volumeSlug/:chapterSlug?
/tools/:toolSlug?
/changelog
```

Development also exposes `/test` for component and interaction testing. Unknown URLs use the in-app 404 view, and the build generates a `404.html` suitable for static hosting.

## Features

### Content and Reading

- article list and detail views with combined keyword, tag, and year filtering
- novel volumes, chapter navigation, persisted reading position, and reader settings
- Markdown code highlighting, footnotes, task lists, math, callouts, and a custom chat format
- Obsidian-style image references, banners, and lazy image loading
- responsive typography, sidebars, and reading progress for desktop and mobile

### Search and Discovery

- open global search with `Ctrl/Cmd + K`
- static search indexes generated by Pagefind after the production build
- combined filters for content type, tag or volume, and year
- a separate full-text search and filter interface in the blog list
- URL-synchronized search state for sharing and navigation

### Comments and Local State

- Giscus comments for articles and novel chapters
- discussions attached to individual paragraphs
- optional bulk paragraph-comment counts API
- browser-local theme, reader settings, and reading position
- built-in migration and cleanup for older local-storage formats

### SSG, SEO, and Static Hosting

- fetches articles, the novel catalog, and changelogs before the build to create one SSG data snapshot
- generates static article routes while keeping server-rendered and hydration data consistent
- emits canonical links, Open Graph, Twitter Card, and JSON-LD metadata through Unhead
- generates the Pagefind index and a static-hosting-friendly 404 page after rendering
- includes `wrangler.jsonc` for serving the `dist/` directory as Cloudflare static assets

## Quick Start

### Install dependencies

```bash
pnpm install
```

### Start the development server

```bash
pnpm dev
```

The development server listens on all network interfaces by default.

### Build for production

```bash
pnpm build
```

The build generates the SSG snapshot, prerenders the site, and creates a Pagefind index in `dist/`. The article and novel sources must be reachable during the build.

### Preview the production build

```bash
pnpm preview
```

## Environment Variables

`.env.development` and `.env.production` provide environment-specific content and service endpoints:

```bash
VITE_BLOG_RAW=
VITE_NOVEL_RAW=
VITE_SERVER_ADDRESS=
VITE_RANDOM_HERO_API=
VITE_COMMENT_COUNTS_API=
VITE_GISCUS_CSS_RAW=
```

| Variable                  | Purpose                                                                              |
| ------------------------- | ------------------------------------------------------------------------------------ |
| `VITE_BLOG_RAW`           | Base URL for the article index, Markdown, and images; required for production builds |
| `VITE_NOVEL_RAW`          | Base URL for the novel index and chapter Markdown; required for production builds    |
| `VITE_SERVER_ADDRESS`     | Default Minecraft server queried by the tools page                                   |
| `VITE_RANDOM_HERO_API`    | Random homepage background endpoint                                                  |
| `VITE_COMMENT_COUNTS_API` | Optional paragraph-comment count endpoint                                            |
| `VITE_GISCUS_CSS_RAW`     | Base URL for custom Giscus theme assets                                              |

`scripts/generate-routes.mjs` reads `.env.production` before the build. Do not commit private credentials; only values intended for client-side exposure should use the `VITE_` prefix.

## Project Structure

```text
src/
  components/
    blog/          # article list and reader
    novel/         # novel catalog, chapter info, and reader
    reader/        # Markdown, paragraph comments, and reader settings
    layout/        # navigation, global search, and page layout
    ui/            # shared UI components
  composables/     # reusable filters, scroll, modal, and image logic
  services/        # content, comments, server, and background APIs
  stores/          # theme, changelog, and reading state
  router/          # routes and build-generated SSG data
  utils/           # Markdown extensions, local storage, and update notices
  views/           # route-level pages

scripts/
  generate-routes.mjs       # generates static article routes and the SSG snapshot

mock/
  article/                  # local articles, images, and index
  novel/                    # local chapters, index, and index generator

public/
  assets/                   # images, fonts, and icons
  archive/                  # archived legacy static pages
  changelog.json            # version history data
```

## Content and Build Notes

- Blog and novel content are maintained in [theWake](https://github.com/KoMoriSam/theWake) and [theHorizon](https://github.com/KoMoriSam/theHorizon); `mock/` contains local content mirrors.
- `src/router/ssg-data.generated.js` is generated automatically and should not be edited by hand.
- Giscus configuration is centralized in `src/constants/config.js`.
- Article and novel APIs live in `src/services/api-articles.js` and `src/services/api-chapters.js`.
- Changelog data comes from `public/changelog.json`.
- `pnpm deploy` publishes `dist/` to the repository's `gh-pages` branch; Cloudflare static asset settings live in `wrangler.jsonc`.

The project primarily targets recent versions of Chrome, Firefox, Microsoft Edge, and mainstream mobile browsers.
